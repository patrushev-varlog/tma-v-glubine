# Локации: карты, по которым ходит герой

Прототип локации (поток G плана `review/07-next-steps.md`, шаг 3 DESIGN.md): сцена истории идёт не на
экране текста, а на изометрической карте. Первая карта — двор Эшмура, на ней две сцены пролога:
облава ночью (`raid`, бой 1) и пепелище утром (`ashes`, Олдрик и улики). В главе 1 на картах идут четыре
сцены шахт: пост у ворот (`mine_gate`), лагерь надсмотрщиков (`mine_cage`), бараки (`mine_barracks`) и площадка
подъёмника (`mine_lift`); на них закоулки, подсказки и место охоты за фонарём штейгера.

## Как сцена попадает на карту

`data/locations/index.json` говорит, какие сцены идут на какой карте:

```json
{"scenes": {"raid": "ashmoor", "ashes": "ashmoor"}}
```

Когда история входит в такую сцену, экран истории передаёт её первую строку экрану локации
(`Game.pending_tail`) и уходит на `scenes/location_screen.tscn`. Сцена без карты — обратно на экран
истории. Куда идти, решает `Game.screen_path()`; так же выбирают экран загрузка сохранения и экран
боя после победы.

## Объект на карте вместо кнопки: тег `#obj:`

Вариант выбора в Ink с тегом `#obj:<id>` — это объект карты. Пока история ждёт только такие
варианты, панель диалога убрана и игрок ходит: подходит к объекту и осматривает его. Обычные
варианты остаются кнопками в панели. Если варианты смешаны, все показываются кнопками.

```ink
= clues
+ {not clue_crown} [Осмотреть телегу у колодца. #obj:cart] -> clue_crown -> clues
+ {not clue_list} [Поднять бумагу у колеса. #obj:list] -> clue_list -> clues
+ [Пойти по колее на север. #obj:road] -> clue_track -> leave
```

Тег стоит внутри скобок, поэтому в текст истории не попадает. На экране истории без карты такие
варианты — обычные кнопки, так что история проходится и без карт (самопроверка, тесты).
Текст варианта виден на карте: в списке «На карте» и в подсказке «Enter — Осмотреть телегу».

Тест `test_location.gd` проходит пролог с разными выборами и проверяет, что у каждого `#obj:`
есть объект на карте этой сцены и до него можно дойти от точки входа.

## Свободный осмотр: поле `explore`

Объект с полем `explore` — закоулок, тайник, человек для разговора или место охоты (story/exploration-plan.md).
Его можно осмотреть всякий раз, когда герой ходит по карте, то есть пока история ждёт вариантов `#obj:`.
Осмотр запускает узел Ink в отдельном потоке (`StorySession.explore`, story/ink/explore_common.ink), строки
идут в панели, необязательный бой — на экране боя, потом герой снова ходит. Подпись в подсказке — ключ
`label` из `i18n/location.csv` («Enter — Осмотреть караулку Хольта»). В списке «На карте» такие объекты
не показываются: их надо найти. Узел сам помнит, что уже осмотрено, и во второй раз отвечает коротко.

```json
{"id": "holt_hut", "cell": [11, 8], "size": [2, 2], "sprite": "mines/guard_hut", "explore": "ch1_look_holt_map", "label": "LOC_CH1_HOLT_MAP"}
```

У объекта-выхода поле `leave_check: <глава>` — точка невозврата охоты: перед выбором варианта экран вызывает
`hunt_leave_check(<глава>)`. Если подсказки собраны, а место не осмотрено, Гаррет останавливает героя; решил
вернуться — герой остаётся на карте, решил идти — вариант выбирается. Так устроен рычаг клети в главе 1.

Чтобы на карте можно было ходить после боя, сцена главы ставит вариант-выход с `#obj:` там, где отряд
свободен (глава 1: «Идти по штреку…», «Сесть у холодного очага», «Зайти в караулку…», «Дёрнуть рычаг клети»;
глава 2: «Идти дальше по штреку», тропа беглых, стол Ренны, «Спуститься по лестнице» у шлюза).

## Формат карты: `data/locations/<id>.json`

| Поле | Что это |
| --- | --- |
| `size` | `[ширина, высота]` в клетках. |
| `legend`, `ground` | Пол: строки по одной на ряд `y`, символ — клетка `x`; `legend` переводит символ в тип пола. |
| `variants` | Варианты карты: `tint` — цвет освещения (ночь, утро), `ground_swap` — замена типов пола. |
| `scenes` | Сцены на этой карте: `variant` и `spawn` — клетка, где герой появляется. |
| `objects` | Объекты, по одному в строку. |
| `wall` | Стены штреков: `{"char": "#", "sprites": [...]}` — на каждой клетке пола со знаком `char` встаёт куб скалы (рисунок по клетке из списка). Дальние от камеры стены — кубы, ближние — низкий уступ, чтобы не закрывать героя. Карты шахт собирает `tools/mine_maps.py`, он же обводит штреки этим кольцом; затопленные выработки главы 2 — `tools/flood_maps.py` (пол `flood_wet`, `flood_wade` — вода по пояс, герой в ней по пояс; `flood_deep` — не пройти). |

Поля объекта:

| Поле | Что это |
| --- | --- |
| `id` | Имя; его ставят в `#obj:`. |
| `kind` | `box` — блок (дом, изгородь, колодец), `figure` — человек, `tree`, `decal` — плоское на земле (люк, бумага, колея, тела, могилы), `fire` — огонь со светом. |
| `cell`, `size` | Левая верхняя клетка и размер в клетках (по умолчанию 1×1). |
| `sprite` | Рисунок из `art/tiles` (`village_morning/house`): один на весь объект, низ рисунка у передней клетки. С `"each": true` — на каждой клетке (изгородь, могилы), с `"flat": true` — под людьми (люк, бумага). |
| `unit`, `face` | Анимированный персонаж из `art/units` (`zombie`, `brandt`) и куда смотрит: `se`, `sw`, `ne`, `nw`. |
| `image`, `face` | Статичный персонаж из `art/units/static/<image>/<face>.png` (`oldrik`, `south-west`). |
| `height`, `color`, `top`, `head`, `shape`, `mark`, `lift`, `small` | Как рисовать заглушку, если рисунка нет. |
| `solid` | Нельзя пройти (по умолчанию да, у `decal` — нет). |
| `variants` | В каких вариантах карты есть объект (по умолчанию во всех). |
| `looks` | Другой вид в варианте: `{"morning": {"sprite": "village_morning/house_burned"}}` — дом сгорел. |
| `if` | Когда виден: имя переменной Ink (`buried_neighbors`), `имя=значение` (`ch1_choice=riot`), `won:<бой>` (`won:prologue_1`), `!` — отрицание. |
| `explore`, `args`, `label` | Узел осмотра Ink, его аргументы и подпись (см. «Свободный осмотр»). |
| `leave_check` | Номер главы: перед уходом через этот объект — проверка охоты. |
| `light` | Светильник: тёплый свет на этой высоте над клеткой (фонари на столбах в шахтах). |

Координаты — изометрия «ромбом вниз»: `x` растёт вправо-вниз по экрану, `y` — влево-вниз, клетка
(0, 0) — верхний угол карты. Ромб клетки 64×32, как в `art/PROMPTS.md`.

## Управление

| | Ходить | Осмотреть |
| --- | --- | --- |
| Мышь, тач | клик или тап по клетке (путь показан точками) | клик по объекту: герой подходит и осматривает |
| Клавиатура | WASD, стрелки — шаг по экрану | Enter или пробел рядом с объектом |
| Геймпад | левый стик, крестовина | A рядом с объектом |

«Вверх» на стике — вверх по экрану, а не вдоль оси карты: из восьми соседних клеток берётся та,
что ближе к направлению стика. Пути — `AStarGrid2D`, по диагонали только если оба соседних
прохода свободны. Журнал, меню и быстрые сохранения — как на экране истории.

## Бой и обратно

Тег `# battle:<id>` на строке: панель показывает «В бой», затемнение и экран боя
(`location_screen.gd`, `_start_battle` → `Game.start_battle()` и `Game.BATTLE_SCENE`). После победы экран
боя вызывает `Game.finish_battle(тьма)` и возвращается на `Game.screen_path()`, то есть снова на карту. Объекты с условием `won:<бой>`
меняются сами: мертвецы у изгороди пропадают, у телеги появляются Брандт и факелы.

## Сохранения

Позиция героя на карте — `StorySession.map_pos` (`{"location", "x", "y"}`), лежит в сохранении
полем `map`. Это не событие журнала: на входе в новую сцену она сбрасывается, и герой встаёт на
`spawn`. Старые сохранения без `map` загружаются с героем на точке входа.

## Графика

Графика K3 (`tools/import_art.py`): пол — `res://art/locations/tiles/<тип пола>.png` (верхний ромб 64×32
утренних тайлов деревни; ночь даёт оттенок варианта), объекты — по `sprite`, герой — лист анимаций по классу
и полу (стойка и ходьба в четыре стороны). Чего нет, рисуется кодом (`location_art.gd`, `location_view.gd`):
ромбы пола с шумом, блоки клетка за клеткой, фигуры-заглушки. Огонь — по-прежнему кодом со светом `PointLight2D`.
