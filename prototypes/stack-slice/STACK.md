# Итоги технического среза стека (поток E)

Срез сделан 12 октября 2026 по решению 7 из [review/06-improvement-plan.md](../../review/06-improvement-plan.md): проверить стек до того, как писать новые главы в Ink. Проект среза лежит здесь, в `prototypes/stack-slice`; как его запускать, описано в [README.md](README.md).

Коротко: **основной стек работает**. Ink идёт через GodotInk на Godot 4.7.2 .NET и проигрывает всю историю так же, как `inkjs`. Запасной путь на чистом GDScript проверен на тех же прогонах. Сборки под macOS, Windows, Linux и Android собираются. Английский текст лежит в параллельных файлах Ink, и автоматическая проверка ловит расхождение логики между языками. Геймпад управляет всем экраном. Чего контейнер проверить не может: запуск на Mac M1, Windows и Android-телефоне, настоящий геймпад и Steam Deck, генерацию портрета. Эти проверки — шаги для Валерия в конце документа; запуск на Mac, Windows и Linux дополнительно проверяет CI.

## 1. Ink в Godot

### Выбранный путь: GodotInk + Godot 4.7.2 .NET

- Плагин [GodotInk](https://github.com/paulloz/godot-ink) (MIT, master `49e35b5` от июля 2026) лежит в `addons/GodotInk`. Внутри него официальный рантайм Ink от inkle (`ink-engine-runtime.dll` 1.2.0). Плагин скачивает его при первой сборке C#.
- Игра пишется на GDScript, как прототип боя. Своего кода на C# один файл: [`scripts/story/InkLoader.cs`](scripts/story/InkLoader.cs), 25 строк. Остальное GDScript вызывает у `InkStory` напрямую.
- Вся игра говорит с Ink через обёртку [`scripts/story/story_runner.gd`](scripts/story/story_runner.gd). Поэтому рантайм меняется заменой одного файла.
- История подаётся в Godot как JSON. Его собирает `tools/ink_tool.mjs` из `story/ink` через `inkjs` 2.3.2: это тот же компилятор, которым сюжет проверяется с начала, и тот же формат (ink 1.2), что у рантайма. JSON лежит в репозитории, поэтому для запуска Node не нужен. Node нужен, только чтобы пересобрать JSON после правки `.ink`.

**Чем проверено.** Тест `tests/run_tests.gd` прогоняет историю на GodotInk и сравнивает прогон с эталоном `inkjs` (`tests/reference.json`). Сравнивается каждая строка, каждый тег, тексты вариантов и все 95 переменных в конце. Выборы делает одинаковый в обоих местах генератор. Каждые три выбора состояние сохраняется, история создаётся заново и загружает сохранение.

| Что | Прогонов | Совпало |
|---|---|---|
| Вся история: пролог — главы 1–5 — одна из концовок; 4 класса × пол героя × пол супруга × 4 набора выборов | 64 | 64 |
| Сцена 1 пролога на русском | 128 | 128 |
| Сцена 1 пролога на английском | 128 | 128 |

**Скорость** (контейнер, 4 ядра x86; на M1 должно быть не медленнее): загрузка JSON всей истории — 149 мс, вся игра без пауз — 138 мс, самый долгий шаг между выборами — 39 мс, сохранение и загрузка состояния — 2–8 мс при размере 2 КБ.

**Что нашлось по дороге:**
- **Баг в GodotInk:** `InkStory.Create(json)` не создаёт рантайм, и первый же вызов падает с `NullReferenceException`. Обход — наследник `JsonInkStory` в `InkLoader.cs`, он задаёт JSON так же, как импорт `.ink` в редакторе. Стоит завести issue автору плагина.
- Импортом `.ink` внутри редактора (его умеет GodotInk) в срезе не пользуемся. Причины: JSON одинаков для обоих рантаймов, проверяется в CI и ровно он попадает в сборку.

### Запасной путь: inkgd, чистый GDScript, без .NET

- [inkgd](https://github.com/ephread/inkgd) (MIT, ветка `godot4`, `fea9098`). Это порт того же рантайма на GDScript. Лежит в отдельном проекте [`fallback-inkgd/`](fallback-inkgd/), потому что его классы называются так же, как у GodotInk (`InkStory`, `InkChoice`, `InkList`), и в одном проекте они конфликтуют.
- Обёртка [`fallback-inkgd/scripts/story_runner.gd`](fallback-inkgd/scripts/story_runner.gd) повторяет основную. Тот же эталон пройден: 4 полные истории и по 4 прогона сцены на двух языках совпали с `inkjs`.
- **Цена.** Загрузка JSON всей истории — 1,7 с, вся игра без пауз — 2,5 с, самый долгий шаг — 221 мс. Это в 12–18 раз медленнее GodotInk. На ПК терпимо, на телефоне будет в несколько раз хуже: тогда историю придётся делить на JSON по главам.
- **Риск.** Последний коммит inkgd — январь 2024, релизов под Godot 4 нет. Если перейдём на него, порт придётся поддерживать самим.

**Когда переходить на запасной путь:** если .NET-экспорт сломается на целевой платформе (Android помечен в Godot как экспериментальный, iOS ещё не проверяли); если понадобится демо в браузере (C#-проекты Godot 4 в веб не экспортируются); если GodotInk перестанут поддерживать. Как переходить: заменить `story_runner.gd` на версию из `fallback-inkgd`, удалить `addons/GodotInk`, `InkLoader.cs` и `.csproj`, собирать обычным Godot без .NET.

## 2. Экспорт

Пресеты лежат в [`export_presets.cfg`](export_presets.cfg). Сборки собраны в контейнере из Godot 4.7.2 .NET и официальных шаблонов экспорта.

| Платформа | Сборка | Размер | Проверка |
|---|---|---|---|
| macOS | universal `.app` в zip (x86_64 + arm64), ad-hoc подпись | 121 МБ | Собрана. Запуск на macOS — CI (`macos-14`, Apple silicon) и Валерий на M1 |
| Windows | x86_64 `.exe` + папка .NET | 182 МБ | Собрана. Wine в контейнере падает даже на пустом Godot, поэтому запуск проверяет CI (`windows-2022`) |
| Linux / Steam Deck | x86_64 + папка .NET | 148 МБ | Собрана, самопроверка пройдена: вся история за 1 с |
| Android | APK arm64, отладочный ключ | 100 МБ | Собран. Запуск — на телефоне Валерия |

**Самопроверка сборки:** `TmaStackSlice -- --selftest` проигрывает всю историю на рантайме внутри сборки и выходит с кодом 0 или 1. Так без рук видно, что C#, рантайм Ink и файлы истории попали в сборку.

**Что пришлось поправить:**
- Для macOS universal и arm64 нужно включить импорт текстур ETC2/ASTC (`project.godot`).
- Шаблон Android в Godot 4.7 собран под .NET 9, а ПК-сборки — под .NET 8. В `StackSlice.csproj` для Android стоит `net9.0`, поэтому для Android-сборки нужен .NET SDK 9 или новее.
- Экспорт C# на Android Godot всё ещё помечает как экспериментальный. Это главный аргумент держать запасной путь в рабочем состоянии.
- Рантайм .NET добавляет к ПК-сборке около 77 МБ. Для игры из Steam это приемлемо.

**До релиза в Steam (не часть среза):** для macOS нужна подпись Developer ID и нотаризация (аккаунт Apple Developer, $99 в год), иначе Gatekeeper ругается. Для Steam Cloud, достижений и экранной клавиатуры Steam Deck нужен GodotSteam. Его стоит подключить отдельным шагом, когда появится аккаунт Steamworks.

**CI:** [`.github/workflows/stack-slice.yml`](../../.github/workflows/stack-slice.yml) на каждый PR, затрагивающий срез или `story/`, делает следующее:
- проверяет, что JSON свежий и языки совпадают;
- гоняет тесты на GodotInk и inkgd;
- собирает все четыре платформы;
- запускает самопроверку на macOS, Windows и Linux;
- выкладывает сборки артефактами на 14 дней.

Минуты macOS в приватном репозитории считаются с коэффициентом 10, поэтому сборки на macOS стоит потом оставить только по кнопке.

## 3. Английские строки в Ink

### Выбрано: параллельные файлы `story/ink-en/`

- Английский текст лежит в `story/ink-en/` с той же структурой файлов, что `story/ink/`. Переведена сцена 1 пролога: [`story/ink-en/prologue/01_evening.ink`](../../story/ink-en/prologue/01_evening.ink) и [`common.ink`](../../story/ink-en/common.ink).
- **Логика обязана совпадать, текст свободен.** Переводчик сохраняет строки, выборы, теги (`# spk:`, `# mood:`, `# battle:`), переходы, `VAR` и `~` в том же порядке. Внутри строки он волен менять порядок слов, убирать `h()`/`s()`, где в английском нет рода, и добавлять, где он есть (his/her).
- **Проверка:** `node tools/ink_tool.mjs parity` (входит в `check` и в CI) проигрывает русскую и английскую версии с одинаковыми выборами: 16 сочетаний героя × 12 наборов выборов = 192 прогона. Сравниваются число строк и их теги, число вариантов в каждом выборе и все флаги в конце. Если, например, у реплики героя потерян тег `spk:hero`, проверка показывает первую расходящуюся строку обоих языков.
- **Смена языка посреди сцены** работает через журнал выборов: история на другом языке проигрывается с теми же выборами (`StoryRunner.switch_language`). Родное сохранение Ink привязано к конкретному JSON. Поэтому предлагаем для игры такую схему сохранения: родное состояние на начале сцены плюс журнал выборов внутри сцены. Тогда сохранения переживут и смену языка, и правки текста в патчах после релиза.
- **Интерфейс** (кнопки, подсказки) переводится обычными средствами Godot: [`i18n/ui.csv`](i18n/ui.csv) по ключам. Это то, что DESIGN.md называет «таблицами перевода»; к тексту Ink они не применяются.

**Почему не ключи.** С ключами (`# id:pro_01_0012` у каждой строки и таблица переводов) логика хранится в одном месте. Но сценарий перестаёт читаться, а строки со встроенной логикой (`{h(...)}`, `{sp()}`, условия внутри фразы) в таблицу не ложатся: переводчику пришлось бы повторять разметку Ink в ячейке. Для текста, где почти каждая третья строка зависит от пола героя или супруга, параллельные файлы проще, а автоматическая проверка закрывает главный их риск — расхождение логики.

**Запасной вариант — ключи строк**, если перевод будет делать сервис, который принимает только таблицы. Тогда тот же `ink_tool.mjs` выгрузит строки в CSV и соберёт их обратно; логика останется в русском файле.

**Глоссарий, который надо утвердить:** Эшмур → *Ashmoor*, супруг по умолчанию Эйла → *Eila*. Новые имена стоит сразу вносить в общий глоссарий, чтобы переводчик не изобретал их заново.

## 4. Геймпад и Steam Deck

Один экран ([`main.tscn`](main.tscn), [`scripts/main.gd`](scripts/main.gd)): диалог сцены 1 пролога, кусок поля 6×4 с Гарретом и крепью, портрет по Тьме. Всё делается мышью, клавиатурой или геймпадом.

| Действие | Геймпад (Xbox / Deck) | Клавиатура |
|---|---|---|
| Дальше / выбрать вариант / шаг Гаррета | A | Enter, пробел |
| Перейти между вариантами, двинуть курсор | крестовина, левый стик | стрелки, WASD |
| Поле ↔ диалог | View | Tab |
| Язык RU/EN | Y | L |
| Набор графики | X | T |
| Стадия Тьмы − / + | LB / RB | Q / R |
| Сцена заново | Menu | F5 |

- Подсказки на экране меняются под последнее устройство: клавиатура, Xbox, Steam Deck, PlayStation (✕ ○ □ △) или Nintendo (у него нижняя кнопка подписана B).
- **В Godot 4.7 по умолчанию `ui_accept` и `ui_cancel` не реагируют на кнопки геймпада**: на геймпад повешены только крестовина и стик. Кнопки добавляет [`scripts/input/input_setup.gd`](scripts/input/input_setup.gd). Об этом легко забыть в боевом интерфейсе.
- Тест [`tests/gamepad_sim.gd`](tests/gamepad_sim.gd) проходит сцену виртуальным геймпадом: листает строки, выбирает вариант, меняет язык посреди сцены, двигает Гаррета, переключает стадию Тьмы и набор графики и доигрывает сцену до конца. Всего 27 проверок.
- **Вёрстка 1280×800** (экран Deck) и 1280×720 проверены снимками: [`docs/deck_pixellab.png`](docs/deck_pixellab.png), [`docs/720p_english.png`](docs/720p_english.png). Основной текст — 22 px, самый мелкий — 15 px при 1280×800.
- **Открытый вопрос управления полем.** Крестовина двигает курсор по осям сетки: «вверх» означает шаг на северо-восток по ромбу. Нужно понять на живом геймпаде, удобно ли это, или лучше экранные направления.
- **Не проверено, нужно железо или Steam:** настоящий геймпад и Steam Input, Steam Deck, экранная клавиатура для имени супруга (на Deck её вызывает Steam API через GodotSteam).

## 5. Стиль-тест графики и портрет по Тьме

**Поле.** Клавиша T / кнопка X переключает три набора из якорей стиля (`art/anchors`) на одном экране:

| Набор | Снимок | Что видно |
|---|---|---|
| PixelLab: пол, крепь, Гаррет | [`docs/deck_pixellab.png`](docs/deck_pixellab.png) | Цельно, ложится на сетку 64×32 без правок, читается на 1280×800 |
| Retro Diffusion: пол, крепь, Гаррет | [`docs/deck_retro_diffusion.png`](docs/deck_retro_diffusion.png) | На каждом тайле пола генератор нарисовал огонёк, у крепи зелёные основания, Гаррет обрезан по колено; пол не попадает в ромб 64×32 |
| Retro Diffusion (пол, крепь) + PixelLab (Гаррет) | [`docs/deck_mixed.png`](docs/deck_mixed.png) | Персонаж и фон выглядят как из разных игр |

**Вывод для PROMPTS.md:** на поле лучше брать PixelLab целиком, а Retro Diffusion использовать только с чисткой и после повторной генерации пола. Окончательно решают пятеро незнакомых людей (шаг ниже).

**Третий генератор (портрет).** Портрет из универсальной модели (Midjourney/Flux → пикселизация, PROMPTS.md, раздел 8) в контейнере сделать нельзя. Сейчас на экране заглушка: [`tools/make_placeholder_portrait.py`](tools/make_placeholder_portrait.py).

**Портрет по Тьме как композит** ([`scripts/portrait/dark_portrait.gd`](scripts/portrait/dark_portrait.gd), снимок [`docs/portrait_stages.png`](docs/portrait_stages.png)):
- один базовый портрет `hero_base.png`;
- три слоя поверх, они добавляются накопительно: Сумрак — тени под глазами, Мрак — вены у висков и тёмная радужка, Бездна — прожилки и зелёный отблеск глаз;
- шейдер [`skin_swap.gdshader`](scripts/portrait/skin_swap.gdshader) меняет три тона кожи на рампу той же палитры Resurrect 64, поэтому кожа бледнеет без новых картинок и без цветов вне палитры.

Стадия берётся по шкале DESIGN.md: 0–24 Тень, 25–49 Сумрак, 50–74 Мрак, 75–100 Бездна.

**Что это даёт по объёму:** на каждую внешность нужен базовый портрет на каждую эмоцию и **один** набор из трёх слоёв, а не 4 стадии × 5 эмоций. Условие для художника: в портретах одной внешности лицо стоит в одной позиции (глаза и виски на тех же пикселях), иначе слои не лягут.

## Шаги для Валерия

То, что не проверить в контейнере. Пункты 1–3 — минут 15–20.

1. **Mac M1.** После того как CI соберёт PR, на странице проверки (вкладка *Checks* → *stack-slice* → *Artifacts*) скачать `stack-slice-macOS` и распаковать. Первый запуск: правый клик по приложению → «Открыть»; подпись ad-hoc, без этого macOS не пустит. Проверить:
   - текст идёт по Enter;
   - L меняет язык посреди сцены;
   - T переключает графику, Q и R меняют портрет, Tab переводит на поле, Гаррет ходит.
2. **Геймпад на Mac**, если есть любой (Xbox, PlayStation, Switch Pro, по Bluetooth или проводу). Пройти сцену только геймпадом и посмотреть, что подсказки сменились на кнопки этого геймпада. Сказать, удобно ли курсором по полю.
3. **Редактор на Mac** — это проверка, что вам удобно работать с .NET-сборкой:
   - поставить [.NET SDK 8](https://dotnet.microsoft.com/download/dotnet/8.0) (для Android-сборки ещё 9);
   - скачать Godot 4.7.2 **.NET** для macOS;
   - открыть `prototypes/stack-slice/project.godot`, нажать Build (молоток), затем F5.
4. **Android**, если есть телефон: скачать артефакт `stack-slice-Android`, поставить APK (разрешить установку из неизвестных источников), пройти сцену касаниями. Особенно важно, потому что C# на Android в Godot экспериментальный.
5. **Портрет для стиль-теста:**
   - сгенерировать один портрет героя в Midjourney или Flux по PROMPTS.md, раздел 8 (STYLE_PORTRAIT + описание героя-волшебника из 4.1), в 1024 px;
   - загрузить его в чат проекта. Пикселизацию в 128×128 и перевод в Resurrect 64 сделаю здесь, как с якорями.
   
   Слои Тьмы для настоящего портрета лучше дорисовать в Aseprite по образцу заглушки, первый черновик слоёв могу сделать и я.
6. **Стиль-тест на людях:** показать снимки `docs/deck_*.png` (или живой экран, переключая T) пятерым незнакомым людям. Вопрос: «персонаж и пол — из одной игры?».
7. **Утвердить глоссарий:** Ashmoor, Eila.
8. **Steam Deck**, если будет доступ: скопировать Linux-сборку и запустить из режима рабочего стола. До аккаунта Steamworks это необязательно.

Когда пункты 1–4 пройдены, срез можно считать закрытым, а писать главы в Ink дальше черновиков (условие плана).
